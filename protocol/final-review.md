# Незалежна технічна перевірка перед повним клоном

Початковий range: 5db4dd0e99a77c3d9ef24f1d6a458cc58ae02293..dc1f680b02fd13201809db35906cf228ed50321d. Read-only reviewer; без API-прогонів, змін index або файлів. Перевірено первинні хеші, membership, результати та тарифні суми чотирьох записів; 27/27 тодішніх тестів PASS.

## Виправлено одним проходом

1. Успішний /chat і помилка trace lookup: request_id тепер збережений, response повертається, є trace_error; ціна береться з reported або лишається null. Два нові параметризовані тести RED→GREEN.
2. Пошкоджений запис для compare: missing/invalid id, passed, null condition тепер дають diagnostic/exit1 замість порівнюваності або traceback. П’ять нових тестів RED→GREEN. Збережено перевірку відповідності списків ID та фактичної моделі.
3. Непридатний usage, який upstream зводить до0/0, не означає безкоштовний виклик. Перевіряю цілі невід’ємні лічильники, позитивний input, діапазон кешу; null/непридатне → unknown. Матриця8 перевірок: чотири нові падіння відтворено до виправлення, решта вже правильно відхилялись. Після виправлень **42/42 PASS** =20 курсу +22 reporting/cost регресії; фактичний compare лишився exit0 з тими самими3 ID.

## Відкладений minor

Для некоректного заголовка промпту й активного overlay функція поверне unknown+D07, а не буквальне unknown. У всіх п’яти потрібних основних записах використовуються коректні заголовкиbase.v1/base.v4; це не змінює їх доказ. Залишаю як вузьке обмеження, не перезаписую записи й не додаю зайвого платного повтору. Такі unknown-записи не використовую як доказ версії.
