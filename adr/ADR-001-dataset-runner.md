# ADR-001: Межа між dataset і runner

**Статус:** Accepted
**Контекст:** L12 — відтворюваний eval-контур

## Контекст

Набори в `sets/` визначають, які сценарії перевіряються. `run_eval.py` відповідає за їх виконання. Змішування тестових даних із логікою запуску ускладнює відтворення результатів і порівняння версій промптів.

## Рішення

Dataset є незмінним джерелом тестових сценаріїв. Runner читає набір, перевіряє його структуру, обчислює `set_hash` за вмістом і передає кейси на виконання.

**Обмін через межу:**

- Dataset → Runner: ID кейсу, вхідні дані, очікування та метадані сценарію.
- Runner → Reports: результати виконання, `set_hash`, `prompt_version`, `profile`, `judge_model`, `rubric_version`, `elapsed`.

## Ціна рішення

Потрібні окрема валідація структури наборів, стабільна серіалізація для обчислення хешу та підтримка сумісності форматів.

Натомість отримуємо можливість порівнювати різні прогони на ідентичних даних.

## Чого не робимо

- Runner не змінює `sets/` під час виконання.
- Не генеруємо й не виправляємо тестові кейси автоматично.
- Не змінюємо очікуваний результат залежно від відповіді моделі.
- Не вважаємо прогони порівнюваними без перевірки `set_hash`.

## Коли переглянемо

Якщо виникне потреба в динамічних наборах, параметризованих сценаріях або новому форматі dataset, переглянемо контракт, зберігши версіонування й відтворюваність.
